The result includes the exact 35 legacy-to-proposed LED record route pairs and hashes of the package route/provider code, project lockfile/patch, proposal and rule inputs. `check.test.mjs` covers the package's invalid, reserved and duplicate guards and exact deterministic result.

**Result:** Proposed ID and record-route syntax passes the installed 0.3.0 functions. No proposed anchor ID is invalid; no record route or integration anchor collision appears in this inspected corpus. All 35 legacy LED record routes would change, so C5 must review old paths and fragments before cutover. A route-syntax pass does not prove the generated site or redirects work.

None of the nine current calculation IDs collides with PD, so this is not a present anchor collision. The installed Python rule validator derives expression variable names from `fact_ids` (`fact-id` to `fact_id`); applying the structured translation alone would leave all nine calculation expressions referring to old symbols. A later serialized canonical implementation must review each calculation ID, structured fact list and expression together, with validator/scenario tests. `result.json` lists every affected calculation and old symbol. No historical rule or proposal byte was changed here.
