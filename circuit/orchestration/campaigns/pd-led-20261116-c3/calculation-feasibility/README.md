# C3f integration calculation feasibility audit

This bounded follow-on starts from independently accepted C3e route-audit head `4962df857d995ed8de5e363507a0c67ba378e08f` on isolated branch `codex/c3f-calculation-feasibility-20261116-01`. Only this new directory is written. The accepted [PD/LED plan](../../../pd-led-unification.md) requires a single evidence corpus, while canonical identity, CAD, placement, publication and old-link decisions remain held.

`audit.py` recomputes C3c's 393-input source-locked proposal and checks hashes again for both integration-rule files and all 14 LED fact files it consumes. It binds the installed patched circuit-doc 0.3.0 Python validator code and project lockfile/patch by SHA256. For each of nine LED conditioned calculations, it proposes a source/payload-hash-bound ID and changes fact IDs and matching expression aliases **in memory**. Scenario variables, contextual nonnumeric fact references, conditions, retained result values and all other payload fields remain unchanged. It invokes the installed `validate_calculation` function on each proposed calculation and translated fact-value lookup. `anchor.test.mjs` checks proposed IDs with the installed generator's actual anchor function and locked PD rule input.

The nine focused validator calls pass, covering 19 retained direct results or scenario rows. No original or proposed calculation ID collides with PD. Three calculations list contextual facts that are not arithmetic operands; the installed validator permits that distinction, and the proposal preserves them. `result.json` records exact old/new IDs, fact lists, expressions, preserved scenario variables, source hashes and per-calculation outcomes. The first local draft overconstrained those contextual facts and failed at `calc-q1-steady-vgs`; the audit now follows the installed validator's actual numeric-fact rule. No source file changed during that correction.

Four focused Python tests include deterministic repeat, source-lock tampering and a stale-alias rejection control. One Node test checks the pinned generator anchor contract. Deterministic result comparison and `pnpm circuit:check` also pass. Checks run with two-CPU affinity and a 4 GiB inherited per-process address-space limit. A separate process-group monitor sampled aggregate RSS every 10 ms: observed peaks were 42,040 KiB for Python tests, 66,676 KiB for the Node test, 37,008 KiB for deterministic comparison and 255,876 KiB for `pnpm circuit:check`. These samples are measurements, not a hard aggregate memory cap or proof that an unsampled spike did not occur. Native CAD, merged-corpus validation, generated pages, full build, CI, PR, merge, deployment and physical checks are **NOT RUN**.

These IDs and expression rewrites are proposed feasibility evidence only. Future canonical implementation still needs a serialized, reviewed identity/placement/rule decision and full validator/scenario/generated-route checks on its exact merged corpus. All 463 textual ID locations, SMAJ and other CAD identity holds, DNP placement, publication/private-resource restrictions, #307 and physical acceptance remain unchanged.
