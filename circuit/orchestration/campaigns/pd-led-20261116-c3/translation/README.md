# C3c evidence ID translation proposal

**Issue:** [#317](https://github.com/Takazudo/zudo-pd/issues/317), parent [#308](https://github.com/Takazudo/zudo-pd/issues/308). **Base:** `c5e45fb0392a8040d6ba304d2be4125ef911e707`, the isolated C3b/C4a integration checkpoint. Moya alone manages adoption. This directory is a proposed mapping and test harness; no canonical evidence, inventory, CAD, route, package, generated page, or publication file is changed.

Run `python3 circuit/orchestration/campaigns/pd-led-20261116-c3/translation/propose.py --check` to compare `proposal.json` byte for byte with the source-locked regeneration. Run `python3 -m unittest discover -s circuit/orchestration/campaigns/pd-led-20261116-c3/translation -p 'test_*.py' -v` for focused checks. The script uses Python's standard library and reads the PD and imported LED owner bundles, both inventories and integration rules, both publication selections, and the LED forward-test and observed-run fixtures. Every input file has a SHA256 in `source_locks_sha256`; each mapping row has its definition payload and containing file hash. Any changed input produces a different output or fails `--check`.

The proposal leaves all PD IDs as they are and assigns a separate, source-bound LED ID to **every** LED definition, including equal-payload IDs. This conservatively avoids treating matching IDs as matching identities or evidence. It maps record and line IDs as well as source, fact, coverage, interaction, route, pin-map and rule IDs, so structured references can close in a future combined corpus. The `reference_translation` array gives the source JSON pointer and target ID for each structured occurrence, including `record_ids`, `depends_on`, blocking facts, publication document selections and forward-test references. A duplicate definition anywhere within one side fails generation, even when owners have different names. A missing structured target appears in `unresolved_references`; zero is required before adoption. Proposed IDs are checked against each other and every PD definition ID.

`textual_references_for_manual_review` lists literal ID mentions in prose, locators and conditions. Those strings must be reviewed with their source context before any future rewrite. Arithmetic `expression` identifiers may be local variable names rather than evidence IDs; their dependency arrays and expressions require a paired validator review. The proposal does not rewrite quoted extracts, verdicts, conditions, source availability, citations or historical receipts. A later canonical implementation must validate the translated contract and generated routes on its exact final bytes.
